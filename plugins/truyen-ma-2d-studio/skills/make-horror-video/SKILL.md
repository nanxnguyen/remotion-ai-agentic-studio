# Truyện Ma 2D Studio — horror story videos, drawn by code

Turn a horror idea, script or voiceover into a finished MP4 plus its thumbnail, title and description. Every frame is drawn by code (HTML canvas + optional Three.js), captured in headless Chromium and encoded with ffmpeg — characters stay consistent, Vietnamese text stays crisp, nothing is generated by image/video models. The studio is the Thanh Hai Learn AI 2D engine plus a horror layer: `engine/horror.js` (ghosts that glide, darkness with light holes, flicker, Vietnamese folk-horror props, the signature "hẻm" alley set, 2.5D multiplane, scare timing, VHS, horror title/rule/thumbnail cards), `engine/ditap.js` (Option C — Dạ Hành Dị Tạp 2D pill-body folklore characters with mourning headbands, blind/scarred/faceless variants, blurred ancestor-altar and rural village street sets, black title cards, crisp black-outlined white burn-in subtitles without boxes, and split-color thumbnails), five horror grades, a horror SFX/music library with **hush** ducking, `tools/scare_lint.py`, `tools/vbee_tts.py` and `tools/make_thumb.py`.

**Bundled resources (this skill's base directory):**
- `kit/` — the tested studio. Install it into the workspace as `truyenma-studio/` (`references/install.md`). `kit/examples/hem-demo/` (9 shots using core horror building blocks) and `kit/examples/ditap-demo/` (8 shots in the Dạ Hành Dị Tạp folklore style) are the reference projects.
- `references/horror-trends.md` — **what top horror channels do** (data, formats, lengths, title patterns). Read before choosing the format.
- `references/horror-story-engine.md` — **story + scare architecture** for Shorts, single stories, compilations and long tâm linh episodes; narration writing rules. Read before writing or checking any script.
- `references/folklore-bank.md` — Vietnamese and global legends with safe angles, plus things never to do.
- `references/horror-style-bible.md` — **the horror look**: entity design, reveal ladder, camera grammar, 2.5D, light, editing, captions, don'ts. Read fully before designing shots.
- `references/horror-engine-api.md` — `horror.js` and `ditap.js` APIs, horror styles/moods, shots.json horror fields.
- `references/horror-sound.md` — horror SFX, music moods, hush, layering and levels.
- `references/voice.md` — Vbee narration (env-var credentials), own recordings, pacing.
- `references/packaging.md` — titles, thumbnails, descriptions, chapters, Shorts→long funnel, policy.
- Base engine references (shared with Thanh Hai): `engine-api.md`, `animation-principles.md`, `style-bible.md`, `story-breakdown.md`, `sound-design.md`, `render-qc.md`, `install.md`.

## Golden rules
0. **Ask the video language first** (Stage 0). Talk to the user in the language they write in.
1. **Story first, pictures second.** A weak story cannot be saved by animation. No script leaves Stage 3 until it passes the checklist in `horror-story-engine.md` (hook in the first line, escalation ladder, earned twist, specific sensory details).
2. **Original stories only.** Write new stories or adapt public-domain folklore. Never copy a creator's story, a Reddit/creepypasta post or a book without the author's permission. Never present invented events as news about real people, real addresses or real victims.
3. **Keep the narration intact** once voiced. Never rewrite, drop or reorder spoken words after Stage 4; every shot illustrates the words spoken while it is on screen.
4. **Fear is built, not shown.** Follow the reveal ladder (absence → silhouette → partial → full face only at the peak), keep one practical light, let darkness hide things, and put silence before every hit (`"hush": true` on the shot before a scare). Ghosts glide or snap between frames — never a walk cycle.
5. **No gore.** Suggest, don't show: shadows, aftermath objects, a hand, a sound. Keeps videos advertiser-friendly and scarier.
6. **Draft, look, fix, then render.** Open contact sheets and stills yourself before any long render.
7. **Three user checkpoints:** the script (Stage 3), the style grid (Stage 6), the preview (Stage 9). If the user is away, take the defaults, state what was assumed, continue.
8. **Files are the truth.** Each video lives in `truyenma-studio/projects/<slug>/`; `story/shots.json` owns all timing.

## Stage 0: Video language
Ask one question first, in the user's language: **"Video này dùng ngôn ngữ nào? (Tiếng Việt, English, …)"** (AskUserQuestion when available). If already stated in this conversation, confirm in one line. Map to an ISO code (`vi`, `en`, …). It drives `--lang`, Whisper, fonts and every on-screen word.

## Stage 1: Intake and format
Ask once (AskUserQuestion when available), skipping anything already given:
- **What we start from:** an idea/topic, a finished script, or a voiceover file.
- **Format** (read `horror-trends.md` → formats):
  - **Short** 9:16, 45–60 s — hook 0–2 s, one scare, twist, CTA. For reach and to feed long videos.
  - **Single story** 16:9, 8–15 min — the main growth format for animated horror.
  - **Compilation** 16:9, 15–25 min — "3 chuyện có thật về…" / "3 True … Horror Stories Animated"; fastest way to watch hours.
  - **Long tâm linh episode** 16:9, 30–60 min — narration-led, slower visuals, built for watch time.
- **Channel/brand:** default Hẻm Chuyện Lạ for Vietnamese (house time 02:17, the hẻm set, red accent `#d1121f`). For English, ask the channel name.
- **Voice:** Vbee (Vietnamese, needs env credentials — `voice.md`), the user's own recording, or another TTS file they provide.
- **Resolution:** 1080p (recommended) / 720p / 1440p / 4K. **Captions:** on for 9:16, off for 16:9 by default.

Defaults when away: Vietnamese, single story 10–12 min 16:9, 1080p, style `amhon`, generated music + SFX.

## Stage 2: Install or check the studio
Follow `references/install.md` with these names: copy `kit/` to `truyenma-studio/` in the workspace (skip if present; never overwrite `projects/`), `npm install`, Chromium (`npx playwright install chromium`, or reuse an installed Chrome with `CHROME_PATH`), `pip install numpy scipy faster-whisper`, `python tools/verify_kit.py`, `python tools/doctor.py`. Self-test: `node render.mjs --project examples/hem-demo --sheet --scale 0.4` must write `examples/hem-demo/build/sheets/sheet_01.png` with 9 frames (alley at 02:17, Minh with phone light, altar with glowing portrait eyes, ghost close-up, banyan with lanterns, shadow figure with red eyes in a flashlight beam, hand from a well, VHS rule card, title card). Open it, then delete `examples/hem-demo/build/`.

## Stage 3: Story (skip only if the user gives a finished script — then still audit it)
Read `horror-story-engine.md` and `folklore-bank.md`. Then:
1. **Pitch 3 premises** in one line each (hook + twist hidden), each with a draft title and the thumbnail idea; recommend one. Use real demand signals from `horror-trends.md` (folk village horror, rules horror, everyday-place horror, cổ tích đen, "chuyện có thật" framing).
2. Write the script with the beat skeleton for the format, then the narration. Mark beats inline: `[HOOK] [SETUP] [DREAD] [HUSH] [SCARE] [REVEAL] [BREATHER] [TWIST] [CTA]`.
3. Run the **script checklist** (end of `horror-story-engine.md`), fix every miss, and save inside `truyenma-studio/drafts/<slug>/`: `script.md` (with beats) and `narration.txt` (spoken text only, one line per sentence, numbers written as words).
4. Show the user the logline, the beat outline and the first 30 s of narration. Continue unless they object.

## Stage 4: Voice
- **Vbee:** `python tools/vbee_tts.py --script drafts/<slug>/narration.txt --out drafts/<slug>/voiceover.mp3 --voice <code> --speed 0.95`. Needs `VBEE_APP_ID`, `VBEE_ACCESS_TOKEN`, `VBEE_WEBHOOK_URL` in the environment and HTTPS to api.vbee.vn (runs on the user's machine or a GitHub Actions runner). If it cannot run here, say so plainly and continue with any voiceover the user supplies. Never label a substitute voice as Vbee.
- **Own recording / other TTS:** use the file as is.
- Measure, don't assume: words ÷ voiced seconds. Reference (Nov 2026 Vbee, pauses included): ~183 words/min at speed 1.0–1.05, ~130–150 at a slow 0.9 read. If a Short exceeds 55 s, cut the weakest escalation line, never the twist. Flag lines read too fast.

## Stage 5: Project, timeline, horror shot list
```bash
python tools/new_project.py --name <slug> --voice drafts/<slug>/voiceover.mp3 --script drafts/<slug>/narration.txt --aspect 16:9 --resolution 1080p --title "<title>" --lang vi --style amhon [--captions]
cp drafts/<slug>/script.md projects/<slug>/story/script.md
python tools/transcribe.py --project projects/<slug> --script projects/<slug>/input/script.txt --lang vi --model small   # match must be ≥ 90 %
python tools/beats.py --project projects/<slug>
python tools/visemes.py --project projects/<slug>
```
(With `vbee_tts.py`, `drafts/<slug>/voiceover.mp3.lines.json` already holds exact line timings — use it to sanity-check the transcript.)

Read `horror-style-bible.md` and the base `story-breakdown.md`. Write `story/bible.md` (logline, the entity's rules and look, cast with one signature colour each, locations with mood + key practical light, motifs such as 02:17 or a recurring object, the reveal ladder plan, music plan). Write `scenes/cast.js`. Rewrite `story/shots.json`:
- Contiguous shots cut on phrase boundaries. Pace by beat: dread shots hold 3–6 s with a slow creep; scares cut fast (0.4–1.2 s); median 2.5–4 s for long-form, 1.5–3 s for Shorts.
- Every shot gets `size`, a concrete `scene`, a horror `beat` and a `fear` 0–1 (`horror-engine-api.md`). Put `"hush": true` on the shot before each scare. Add an establishing shot per new location.
- Hook in the first 2–3 s: the anomaly itself, never a logo, channel intro or context.
Run `python tools/shot_lint.py --project projects/<slug>` then `python tools/scare_lint.py --project projects/<slug>`; fix every error and read the fear curve (it must climb, with breathers). Send the user a 5–10 line plan summary and continue unless they object.

## Stage 6: Style choice
Build the 1–2 main sets and 3 representative shots (an establishing wide with practical light, an entity reveal, an insert of the key object). Render the grid:
```bash
node render.mjs --project projects/<slug> --styles amhon,nhang,huyet,vhs,giayma --at <t1>,<t2>,<t3> --scale 0.5
```
Show `build/styles/style_grid.png` with one line each: **amhon** (cold blue-black, one warm practical — default), **nhang** (incense amber, Vietnamese altars and old houses), **huyet** (blood-moon noir — climaxes, curses), **vhs** (found-footage tape, pair with `H.vhs()`), **giayma** (paper-cut folk tale — cổ tích đen). Save the pick in `config.json` → `style`. One style per video; switch only for a deliberate segment (e.g. a VHS flashback).

## Stage 7: Build every shot
Read `horror-engine-api.md`, base `engine-api.md`, `animation-principles.md` and `kit/examples/hem-demo/scenes/shots/demo.js` once. Work in batches of 8–12 shots:
1. Write `scenes/sets/<location>.js` and `scenes/shots/NN_<name>.js` (`registerShot('<id>', {...})`). Use `import * as H from '/engine/horror.js'`.
2. `node render.mjs --project projects/<slug> --sheet --scale 0.5`, open every sheet, check against the QC list below and `render-qc.md`, fix MISSING shots and red error text.
3. Check motion and scares with `--stills` a few frames apart around each beat (before the hush, the hit frame, 0.3 s after), or `--from A --to B --scale 0.5` for a preview clip.

Horror non-negotiables:
- One motivated practical light per shot (lamp, candle, phone, moon) with `H.flicker`; darkness via `H.darkness()` holes, not by making everything black.
- Entity follows the reveal ladder; it appears first in the background, out of focus or in a doorway, before any close-up.
- A camera move in every shot (`H.creep` for dread, `H.punch` on hits, `H.dollyZoom` for realisation, `H.dread` tremble for fear).
- Humans act with `act()`/`exprAt` (scared, shocked, worried), lip-sync only on quoted lines, rim light on every lit figure.
- Atmosphere in every exterior (fog bank, dust, rain, paper money, smoke); 2.5D depth via `H.planes` or `layer()` depths.
- Every scare: hush before → hit SFX on the exact frame → `H.scareFlash`/`H.punch` → hold the image 0.5–1 s → breather.
- Text only for the hook number/time, chapter tags, rule cards and the title; Vietnamese with full diacritics.
- `V()` for every aspect-dependent value; no `Math.random`/`Date.now`.

## Stage 8: Sound
Read `horror-sound.md`. Fill `shots.json` → `music` (dread / haunt / folk / chase / void, plus base moods), per-shot `sfx` (scare, reverse, creak, knock, whisper, musicbox, templebell, drip, static, chime, wail, scrape, breath, heartbeat, footstep…) and `amb` beds (drone, wind, rain, chime, roomtone). Audition with `python audio/mix.py --project projects/<slug>`.

## Stage 9: Render, thumbnail, package, deliver
1. Lint again (both linters), then preview: `node render.mjs --project projects/<slug> --from 0 --to 30 --scale 0.5`. Show the user the opening 30 s (or a contact sheet) before the long render.
2. Final: `node render.mjs --project projects/<slug>` (background for long videos; poll the log, share the ETA). Then `python audio/mix.py --project projects/<slug>` → `out/<title>.mp4`.
3. Thumbnail: read `packaging.md`, write `scenes/shots/thumb.js` (and `thumb2`, `thumb3` variants), run `python tools/make_thumb.py --project projects/<slug> --variants 3`, open the PNGs, pick the strongest.
4. Write `out/publish.txt`: 3 title options (recommended first), description with chapters, tags, pinned comment, Short cut-down plan (`packaging.md`).
5. QC the final file: duration matches, audio present, a 1-frame-per-10-s contact sheet looks right, no red error text.
6. **Google Drive Delivery (Mandatory default):** Upload the final deliverables into the owner's `Videos-shorts` folder (`$VIDEOS_SHORTS_FOLDER_ID`). The folder ID is never hard-coded in this plugin: take it from the `VIDEOS_SHORTS_FOLDER_ID` environment variable, or from the workspace's own instructions (AGENTS.md / CLAUDE.md / a Drive archive doc). If neither defines it, ask the user once and skip the upload rather than guessing. List all children with `gdrive readonly ls "$VIDEOS_SHORTS_FOLDER_ID" --max 0 --json`, allocate `max(N)+1`, create `<N>. <Video title> - <YYYY-MM-DD>` (Asia/Ho_Chi_Minh), and upload 3 verified files:
   - **`<real-video-name>.mp4`** (e.g. `<slug>-final.mp4` — **must use the actual produced video name, NEVER generic `video-final.mp4`**)
   - `thumbnail-youtube.png` (16:9 for long-form, 9:16 for Shorts)
   - `youtube-title-description.txt` (UTF-8)
   Read back folder metadata and always output clickable `https://drive.google.com/...` URLs for the folder and all 3 files immediately upon completion. Do not publish to YouTube/TikTok without explicit authorization.

## QC checklist for horror frames
- Can you tell where the light comes from? Is the entity readable as a shape against its background (rim, glow or a lit wall behind)?
- Is the scariest thing in the frame where the eye goes last (corner, doorway, background), except on the scare frame itself?
- Do consecutive shots change size or angle (no two similar wides in a row)?
- First frame of the video: would it stop a scroll with the sound off?
- Vietnamese text: diacritics correct, ≤ 2 short lines, inside the safe area (9:16: keep 250 px clear at the bottom).
